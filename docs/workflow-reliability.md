# Workflow reliability

Use the versioned workflow for the public audit, conditional and unconditional
entries. It owns routing, evidence binding and the release sequence. Yui's
adapters own proof content, library preparation and fault diagnosis. A proof
gap, a correctable submission and a computation waiting for a dependency have
different consequences at that boundary.

It sends an exact matching rejected packet's findings to the author and requires a revised body. |

## Review and repair

The author and reviewer share the same conditional context projection and the
same mathematical criteria, including conditional packet replay. Review the
exact exported condition, binder and witness that each use requires. Send a
correctable shape error to its current producer before ending the assignment.
Keep independent mathematical judgments distinct from author inspection and
successful structural checks. A valid initial draft can proceed directly. A
located issue can close after one revision when its corrected candidate passes
the same independent standard.

Audit A matches history against the exact mathematical scope and rule version.
A matching receipt carries its original execution and evidence identity. The
read-only index is shared during preparation. Each local review consumes one
packet and the corresponding accepted global scope. Final merged acceptance
still checks current evidence for every required scope. Restore or change only
the affected proof, scope and descendants that actually consume it.

## Dependency and operational boundaries

Inspect downloaded Lean code in the selected environment first. When a missing
compiled import belongs to an exact retained public GitHub source, the import
tool can retrieve that revision and build its in-repository namespace closure
with the existing sandboxed compiler. This path uses fixed Git commands and
the host's HTTPS proxy settings while isolating Git configuration and
credentials. It reads static Lake metadata to locate the module's source root, retries a
failed shallow fetch once within the available budget and reuses the verified
checkout in the owning case. It downloads only the source files the closure
needs. Dependencies outside the namespace use their own
explicit checked bindings. A declared original
environment can be checked separately. Each compiler version needs its own
binaries. A package requiring custom build flags, an additional module in
an already bound namespace, or an actual compatibility port remains an explicit
dependency action with diagnostics. If operator action is needed, the native
dependency receipt can be held for recheck. The text-material route handles
missing readable statements. Use the checked attachment route for a package
requiring explicit preparation. An owned pre-freeze binding never
edits the job manifest. Semantic source review, native signatures and final
dependency trust checks still decide whether the mathematical work is usable.

Use the setup entry to change the machine default toolchain, and verify a newly
prepared request against that selected pair. Existing runtime snapshots and
their environment receipts retain their explicit version.

## Regression obligations

- Audit preparation must scale with the actual historical records and current
  packets. The 100-by-100 regression counts historical reads and graph
  validations. Wall times can be observed without making machine load a verdict.
- Exercise both author and independent-auditor revision origins, including a
  submission containing only changed local bodies, followed by the normal
  complete review and Lean acceptance gates.
- Replay a review of a revised packet and a local repair escalation with stale
  findings. Verify that each can submit in the same assignment after reading the
  actual changes. Test transport interruption separately from a judgment.
- Compile and import actual dependency modules under the configured Lean pair.
  Test the source wait and dependency-repair routes separately, including
  unchanged pins, failed imports and tampered bindings.
- Compare the workflow plan and run the registered Builder audit and real-entry
  regression suite on a stable source version. Fixtures and historical replays
  qualify workflow behavior. Report live proof acceptance and end-to-end timing
  only from the actual scientific runs.
